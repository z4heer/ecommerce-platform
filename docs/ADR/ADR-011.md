** ADR-014 — Enterprise Confirmation Dialog Strategy
Context
Distributed structural implementations across teams frequently introduce inconsistent UI models, broken focus traps, and varying button placements for critical user actions like record deletion.

Decision
We have standardized confirmation workflows on a single standalone, presentation-only component: ConfirmationDialogComponent. This component dynamically resolves state between programmatic MatDialog tokens and native standalone input elements. It uses functional design tokens categorized by severity layers (default, info, warning, danger) to provide clear visual hierarchy across all platform layers.

Consequences
Feature modules are prohibited from creating localized confirmation layouts.

Modals pass pure boolean responses to the calling parent, cleanly separating UI components from underlying business orchestrations.

ADR-011: Enterprise Loading Experience Strategy
Status: Approved

Context: 
Standardizing the interface state model across the application requires a performant, uniform approach to async wait periods that avoids blocking user interactions or causing layout shifts.

Decision:
Adopt a pure presentation-only skeleton engine, replacing heavy spinners with low-overhead CSS bones. The component handles layout logic purely through hardware-accelerated style channels, completely decoupled from operational business models.
